# Четыре лендинга под пять кампаний Директа

**Дата:** 2026-09-02
**Статус:** согласован по секциям в сессии, ждёт проверки собственника перед планом реализации

---

## 1. Контекст

Собственник хочет пустить поисковый трафик из Яндекс Директа на webkoth.com и продавать
услуги внедрения и автоматизации. Спрос снят по 44 фразам Wordstat (Россия, август 2026),
конкуренты и цены собраны по 190 источникам, пятнадцать идей отранжированы по одному
критерию «частота запросов с намерением × типовой чек». Итог исследования лежит в
`business-os/research/2026-09-02-reyting-15-idey-chastota-x-chek.md` и соседних файлах.

Из пятнадцати выбраны четыре страницы под пять кампаний. Две финансовые кампании,
«первичка» и «отчётность», ведут на одну страницу, потому что покупатель у них один:
главбух и финдиректор.

Что уже есть на сайте и переиспользуется: лендинг «Эволюция бизнеса» с шапкой, подвалом,
формой заявки в Telegram и почту (`components/evolution`), 18 кейсов с каруселями и
страницами (`app/data/cases`, `components/cases`), страница стандарта и квиз вердикта на
восемь вопросов с детерминированным движком (`lib/standard/verdict.ts`,
`components/standard`). Спека `/marketplaces` от 2026-08-10 задала образец автономной
RU-страницы; сама страница не строилась и этой спекой заменяется.

**Результат:** четыре страницы, одна сборка, контент в данных, один квиз с пресетами,
заявка с контекстом страницы, счётчик с целями, по которым сравниваются кампании.

## 2. Цели и не-цели

**Цели**

- Одна главная конверсия на каждой странице: заявка на разбор. Вторая: результат квиза,
  который сам ведёт в заявку с контекстом.
- Пять кампаний измеряются одинаково: клики, старт квиза, результат, заявка, цена заявки.
- Контент отделён от вёрстки: правка текста, цен и пресетов не трогает компоненты.
- Все утверждения проверяемы: цифры из кейсов и из исследования спроса, цены как вилки.
- Текст в объяснительном стиле, первое лицо, без длинных тире, без обещаний процентов.

**Не-цели**

- Английские версии. Изменение главной страницы. Оплата, регистрация, личный кабинет.
- Сети Директа, A/B-тесты текстов, CRM, хранение результатов квиза на сервере.
- ИИ в рантайме на страницах: квиз остаётся таблицей решений.

## 3. Аудитория и голос

Четыре покупателя, по одному на страницу:

| Страница | Кто покупает | С какими словами приходит |
|---|---|---|
| `/kontur` | ИТ-ответственный или владелец торговой компании | интеграция с маркетплейсами 1С, интеграция api 1с, синхронизация остатков 1с |
| `/it-director` | владелец компании 10–200 человек без своего ИТ | ит аутсорсинг, аудит ит инфраструктуры, ит директор на аутсорсе |
| `/agent` | владелец, который уже пробовал ИИ и получил нерабочее | ии агенты для бизнеса, внедрение ии агентов, ии агент в компанию |
| `/finance` | главбух, финдиректор, собственник | распознавание первичных документов 1с, автоматизация отчётности, ии для бухгалтерии |

Голос первого лица единственного числа, как на остальном сайте. Возражение «а вы один»
снимается кейсами, где виден объём построенного, и блоком «что стандартизировано».

## 4. Маршруты

Четыре автономные RU-страницы вне сегмента `[lang]`, по образцу `app/banner`:
`/kontur`, `/it-director`, `/agent`, `/finance`. Слаги латиницей: кириллический адрес
превращается в проценты в мессенджерах и отчётах. Страницы индексируются, входят в
`sitemap.ts` и в `llms.txt`.

Параметр `?p=<preset>` открывает квиз на нужном пресете. Для `/finance` это
`?p=pervichka` и `?p=otchet`, по одному на кампанию. Без параметра квиз начинается с
выбора пресета.

## 5. Модель данных

Новый модуль `app/data/landings/`, отдельный от `evolution` и `cases`.

`registry.ts`, то, что не зависит от текста:

```ts
type LandingSlug = 'kontur' | 'it-director' | 'agent' | 'finance'

type LandingMeta = {
  slug: LandingSlug
  skeleton: 'symptoms-first' | 'case-first'   // A или C из секции 6
  heroCase?: CaseSlug                          // для case-first: главный кейс; CaseSlug = ключ реестра кейсов
  cases: readonly CaseSlug[]                   // порядок карусели
  presets: readonly QuizPresetId[]             // пресеты квиза этой страницы
  campaign: string                             // имя кампании Директа для UTM
}
```

`<slug>.ts`, тексты страницы: заголовок, подзаголовок, кнопки, симптомы, шаги «как это
работает», ступени и цены, вопросы и ответы, блок «стандарт и индивидуально».

`presets.ts`, пресеты квиза:

```ts
type QuizPreset = {
  id: QuizPresetId                 // 'kontur-stocks', 'finance-pervichka', ...
  landing: LandingSlug
  label: string                    // «остатки склад ↔ площадки»
  hints: Partial<Record<QuizQuestionKey, string>>   // подсказки к вопросам; QuizQuestionKey = ключи QuizInput
  library: { label: string; href: string }[]        // карточки библиотеки в результате
  meaning: Record<VerdictForm, string>              // «что это значит для вас» по вердикту
}
```

В реестр кейсов (`app/data/cases/registry.ts`) добавляется поле
`landings: readonly LandingSlug[]`, по нему карусель фильтрует кейсы. Кейс может
принадлежать нескольким страницам.

Тесты данных по образцу `cases.test.ts`: слаги уникальны, у каждой страницы есть хотя бы
один пресет и три кейса, все `cases` и `heroCase` существуют в реестре кейсов, у каждого
пресета есть `meaning` для всех форм вердикта.

## 6. Скелет страницы

Один скелет, два порядка. Переключатель в `LandingMeta.skeleton`.

**A, «симптомы первыми»** (`/agent`, `/it-director`): человек приходит с размытой болью,
его сначала надо узнать.

1. Первый экран: заголовок под слова кластера, подзаголовок, кнопка «Разобрать мой
   процесс» со скроллом к квизу, вторая кнопка «Заявка».
2. «Узнаёте себя»: три-четыре симптома аудитории. Без слова «ИИ» в первой строке.
3. Квиз вердикта с пресетами страницы.
4. «Как это работает»: четыре шага и блок «что стандартизировано, что под вас».
5. Кейсы: карусель по тегу страницы.
6. Ступени и цены: вилки.
7. Вопросы: возражения.
8. Заявка.

**C, «кейс первым»** (`/kontur`, `/finance`): человек приходит с конкретной задачей,
кейс убеждает быстрее слов.

1. Первый экран: заголовок, подзаголовок, кнопка «Заявка», кнопка «Посмотреть кейс».
2. Главный кейс страницы: болело → стало, три-четыре характеристики, ссылка на страницу
   кейса.
3. «Как это работает».
4. Квиз вердикта.
5. Ещё кейсы: карусель.
6. Ступени и цены.
7. Вопросы.
8. Заявка.

Шапка и подвал из `components/evolution` (`header-nav`, `footer`), липкая кнопка
`sticky-cta` со скроллом к заявке. Блоки «Как это работает», «Ступени и цены»,
«Вопросы» и «Заявка» одинаковые для всех страниц по устройству, разные по тексту.

## 8. Интерактив: квиз с пресетами

Движок `decideVerdict` из `lib/standard/verdict.ts` без изменений: таблица решений, без
модели в рантайме. На странице сказано: «ответы никуда не уходят, пока вы не нажмёте
кнопку».

Три отличия от квиза на `/ru/standard/verdict`:

1. **Вход через пресет.** Шаг 0 «какой процесс разбираем»: пресеты страницы плюс «свой»
   одной строкой. Пресет не подменяет ответы: факты про эталон и данные знает только
   клиент. Он задаёт подсказки к вопросам на языке аудитории, подбирает карточки
   библиотеки в результате и даёт имя процессу для заявки. `?p=<preset>` пропускает шаг 0.
2. **Восемь вопросов без изменений.** Те же ворота, взвешивание, последствия; тот же
   результат.
3. **Результат ведёт в заявку с контекстом.** Под вердиктом текст `meaning[verdict]` из
   пресета и кнопка «Обсудить этот вердикт». Открывается `lead-dialog` с заполненным
   контекстом в поле `answer`: страница, пресет, вердикт, ответы одной строкой.

Компонент `verdict-quiz` получает пропсы `presets` и `initialPreset`; текущая страница
стандарта передаёт пустой список и работает как раньше.

## 9. Заявка

API `app/api/evolution/lead` остаётся. В `evolutionLeadSchema` добавляется необязательное
поле `source` вида `{ landing: LandingSlug; preset?: QuizPresetId; verdict?: string }`.
Тексты для Telegram и письма выводят его первой строкой:
`/finance · первичка · F4 · эталон есть, данные в 1С, write с подтверждением`.
Это паспорт задачи до первого звонка.

Rate limit, honeypot и проверка времени заполнения без изменений.

## 10. Аналитика и кампании

Счётчика на сайте нет. Ставится Яндекс Метрика в `app/layout.tsx`, номер счётчика из
переменной окружения `NEXT_PUBLIC_YM_ID`; без переменной счётчик не рендерится. Три цели:
`quiz_start`, `quiz_result`, `lead_sent`. События шлются из квиза и из формы. Цели
работают и на странице стандарта.

Пять кампаний Директа, только поиск:

| Кампания | Страница | Ключевые кластеры |
|---|---|---|
| kontur | `/kontur` | интеграция с маркетплейсами 1с, интеграция api 1с, синхронизация остатков 1с |
| it-director | `/it-director` | ит аутсорсинг, аудит ит инфраструктуры, ит директор на аутсорсе |
| agent | `/agent` | ии агенты для бизнеса, внедрение ии агентов, ии агент в компанию, купить ии агента |
| finance-pervichka | `/finance?p=pervichka` | распознавание первичных документов 1с, сервис распознавания документов, распознавание документов цена |
| finance-otchet | `/finance?p=otchet` | автоматизация отчётности, управленческая отчётность, ии для бухгалтерии |

Минус-слова общие: курс, обучение, вакансии, бесплатно, скачать, что это, колледж,
диплом. UTM: `utm_source=yandex`, `utm_medium=cpc`, `utm_campaign=<кампания>`,
`utm_content=<группа>`.

Волны: контур и ИТ-директор; через две недели обе финансовые; через четыре агенты.
Правило остановки на кампанию: 40 кликов без старта квиза или 80 кликов без заявки,
пауза и переписывание объявлений, не страницы. Порог цены заявки назначается после двух
недель данных. Раз в неделю строка результатов в `business-os/execution/`.

Настройка кампаний не входит в план реализации сайта; она делается в Директе после
проверки целей Метрики.

## 12. Правила текста

- Объяснительный стиль, первое лицо, короткие предложения. Без длинных тире, без
  списков через точку с запятой, без «инновационный», «эффективный», «уникальный».
- Каждая цифра имеет источник: кейс на сайте или файл исследования в business-os.
- Цены только вилками и с подписью «после разбора точнее». Процентов эффекта нет.
- Слово «ИИ» не открывает первый экран на `/kontur`, `/it-director`, `/finance`.
- Заголовок `/agent` совпадает с позицией сайта: «ИИ у вас уже есть. Он просто не работает».

## 13. Проверка

- Тесты данных из секции 5.
- Сквозные тесты Playwright: каждая из четырёх страниц открывается; квиз с пресетом из
  `?p=` доходит до результата; кнопка результата открывает диалог с заполненным
  контекстом; API заявки принимает `source` и отвечает 200. Заявочный API в тестах
  подменяется, чтобы не слать в Telegram.
- Сборка: четыре адреса в `sitemap.ts` и `llms.txt`, `npm run lint && typecheck && test`.
- Ручная проверка перед запуском кампаний: цели Метрики срабатывают на всех четырёх
  страницах и на странице стандарта.

## 14. Что фиксируется в business-os после согласования

- Расширение сегмента за пределы маркетплейсов на 1С, финансы и ИТ-аутсорсинг, и цены
  трёх новых страниц как гипотезы. Это расходится с решениями от 14.08 и 31.08 и требует
  отдельного решения, а не правки.
- Отложенные идеи из рейтинга: ERP через партнёра-франчайзи, сервис под процесс внутри
  контура и ИТ-директора, MCP-магазин как контент для YouTube, остальные в очередь.
- Эксперимент с Директом: волны, правило остановки, строка результатов раз в неделю.
