# Корпус AI-вакансий: спрос глазами работодателя

Второй, независимый от Wordstat взгляд на спрос. Вакансия стоит денег и пишется человеком
с бюджетом, поэтому задача в ней описана языком бизнеса. Wordstat меряет спрос покупателей
(кого можно привести на лендинг), вакансии - спрос работодателей (где задача созрела).
**Индексы не складываются.**

Выводы и решения: `business-os/research/2026-09-05-vakansii-ai-spros-otraslej.md`.
Здесь только конвейер и данные.

## Ограничения источника

- `api.hh.ru/vacancies` отдаёт **403**: нужен зарегистрированный app-токен с `dev.hh.ru`.
  Справочники (`/areas`, `/industries`) открыты. Собственник решил без регистрации.
- Поиск отдаёт **только последние 30-45 дней**; `period` и `date_from` игнорируются.
  Корпус - это фотография августа-сентября 2026, не динамика.
- Архив читается по прямому id (`hh.ru/vacancy/<id>`), плотность ~1,05 млн id в месяц,
  но доля AI-вакансий в потоке ~0,2% - ретроспектива стоит 30-80 часов перебора.
- Потолок выдачи - 2000 результатов на запрос (40 страниц по 50).
- ToS hh запрещает автосбор. Держим паузу 2-3 с с разбросом, чекпойнты на диск,
  возобновляемость. При 403/429 - экспоненциальный откат, затем остановка.

## Порядок запуска

```
node marketing/vacancies/scout.mjs        # объёмы по словарю, ничего не собирает
node marketing/vacancies/collect.mjs --stage=a   # поиск -> id и карточки (~250 запросов)
python3 -c "..."                          # фильтр ролей -> kept-ids.json, см. ниже
node marketing/vacancies/employers.mjs    # отрасль, размер, сайт по каждой компании
./marketing/vacancies/run-b.sh            # описания порциями (обходит нехватку памяти)
node marketing/vacancies/facets.mjs       # матрица «запрос x отрасль» из фасета выдачи
node marketing/vacancies/analyze.mjs      # типы задач, медианы, кросс-таблица, насыщение
node marketing/vacancies/outreach.mjs     # аутрич-список -> outreach.csv
node marketing/vacancies/foreign.mjs && node marketing/vacancies/analyze-foreign.mjs
```

Все проходы возобновляемые: повторный запуск пропускает собранное.
`run-b.sh` нужен потому, что длинный процесс убивается системой по памяти -
скрипт завершает node каждые 100 записей.

## Фильтр ролей - самое важное место

Две трети выдачи это **не разработка ИИ**: продавцы, клиентские менеджеры, AI-тренеры
краудсорса, редакторы «для обучения нейросетей». Они упоминают ИИ и попадают в поиск.
Без фильтра «Снежная Королева» с 241 вакансией и «Совкомбанк. Продажи» с 227 определяют
отраслевую картину.

`filter.py` держит два уровня: роль должна быть технической или продуктовой (TECH),
и отсекаются краудсорс, найм, не-ИТ инженеры (STOP). Оставляет 30%.
Плюс потолок 20 вакансий на компанию, иначе «Сбер. IT» с 357 позициями перевешивает всё.

## Заказчик против исполнителя

Решение собственника 05.09: **отраслевая компания - заказчик, ИТ и интегратор - исполнитель**.
Частоты считаются отдельно, иначе картина искажается: в смешанном корпусе на первом месте
агенты (28,8%), у заказчиков - интеграции и 1С (32,9%), а агенты падают на четвёртое.

Классификация - по отрасли работодателя из `employers.jsonl`. Отрасль известна у 70% компаний;
у hh нет отрасли «кадровые агентства» и не заполнен размер у 85%, поэтому агентства
отсекаются по названию, а размер - по числу открытых AI-позиций.

## Что осталось незакрытым

- **Второй индекс не полон.** 23 фразы на замер в `wordstat-todo.md`; главная дыра -
  RAG и поиск по документам (третье место по индексу, спрос покупателей не мерился).
  API Директа в песочнице, частоты снимаются вручную через wordstat.yandex.ru.
- **Ряда нет.** Сбор разовый по решению собственника, поэтому динамика не измеряется.
  Ежемесячный снимок тем же конвейером дал бы её за один вечер в месяц.
- **Аутрич-список требует вычитки**: ИП-физлица, агентства без кадрового слова, вузы.
